# Доповнення 2: склади постачальників, терміни і назви українською

## 1. Склади постачальників (API-ключі постачальників — у програмі)
Сайт бере наявність ТІЛЬКИ з програми. Програма підключає API постачальників (Автотехнікс, Омега тощо) у розділі офлайн-замовлень і зберігає залишки по складах.

Що потрібно в облаці програми (Supabase, проєкт zuhanlspejgizjbwbnda):

1. Таблиця складів постачальників (назву обери сам, напр. `supplier_warehouses`):
   - `id uuid`, `supplier_id uuid` → `suppliers`, `name` (напр. «Омега Львів»), `city`
   - `days_to_store int` — скільки днів товар їде з цього складу до нашого магазину
   - `days_to_ship int` — скільки днів від замовлення до відправки клієнту (включно з доставкою до нас), напр. Автотехнікс будь-який склад = 1, Омега Львів = 3
   - `show_on_site boolean` (default true), `is_active boolean`
   - налаштовується в програмі для КОЖНОГО складу окремо

2. Залишки постачальників по складах (напр. `supplier_stock`): `product_id uuid` → `products`, `warehouse_id`, `qty numeric`, `purchase_price int` (копійки), `updated_at`.
   Товар постачальника зіставляти з нашим `products` за артикулом+брендом, крос-номерами, штрихкодом. Якщо такого товару немає — створювати картку в `products` (is_active = true, qty_on_hand = 0), щоб він міг з'явитися на сайті.

3. Роздрібна ціна для товару, якого немає на нашому складі, рахується в програмі за правилами націнки програми (`category_markups` / `shop_settings.markup_rules`). Закупівельну ціну на сайт не передавати.

4. Представлення (view) для сайту — РІВНО з такими колонками, сайт читатиме його через свою функцію експорту:
```sql
create or replace view public.site_product_offers as
select
  p.id                    as product_id,
  greatest(p.qty_on_hand, 0)              as own_qty,        -- наш склад
  coalesce(s.supplier_qty, 0)             as supplier_qty,   -- сума по складах з show_on_site
  s.min_days_to_ship                      as min_days_to_ship, -- найшвидший склад, де qty > 0 (null якщо ніде)
  s.retail_price                          as supplier_retail_price, -- роздрібна ціна (копійки) для товару під замовлення
  greatest(p.updated_at, coalesce(s.updated_at, p.updated_at)) as updated_at
from products p
left join lateral ( ...твій розрахунок по supplier_stock + supplier_warehouses... ) s on true;
```
   ВАЖЛИВО: коли змінюється залишок постачальника або термін складу — оновлюй `products.updated_at` цього товару (або тригером), щоб сайт за 2 хвилини побачив зміну.

5. Логіка на сайті (робить сайт, для довідки):
   - є на нашому складі → «В наявності: N шт», відправка сьогодні/завтра;
   - немає в нас, але є у постачальника → «В наявності», «Відправка через N дн.» (min_days_to_ship), ціна = supplier_retail_price;
   - ніде немає → товар не показується.
   У кошику біля товару — термін відправки, у замовленні — загальний термін за найдовшим товаром. Менеджер у розділі «Сайт» бачить, з якого складу брати.

## 2. Назви товарів українською
Перейменувати всі товари українською В ПРОГРАМІ (сайт підхопить автоматично протягом 2 хвилин; адреси сторінок на сайті не зламаються — вони тримаються на номері товару).
- Зроби масову дію «Перекласти назви українською» з помічником ШІ: пачками по 50–100, з попереднім переглядом «було → стало» і підтвердженням менеджера.
- Стару назву зберігати (напр. у `products.notes` або окремому полі), щоб пошук за старою (російською) назвою на касі теж працював.
- Правила: бренди, артикули, OEM-номери, в'язкість (5W-40), об'єми (1л, 4л) НЕ перекладати; прибирати службові хвости типу «(12)/216672»; формат: «<Що це> <Бренд> <Модель/Артикул> <Параметри>», напр. «Олива моторна ELF Evolution 900 SXR 5W-40 4л».
